# First 1,000-Lawyer Working Set Build

Date: **2026-09-02**

This is the first scaled execution of the architecture in `docs/FINAL_LEAD_ENGINE_ARCHITECTURE.md` after the 10-request benchmark.

## Target

Create **1,000 unique law-firm website domains** for downstream homepage crawling and service-gap verification.

Initial quality gate:

```text
Google minRating search filter: 4.7
Grounding parsed rating: >= 4.7
Grounding parsed review count: >= 20
business status: OPERATIONAL
Grounding returned Place ID must match discovery Place ID
official website required
dedupe by website domain
```

No Place Details Enterprise calls and no review text were requested.

## What the 92 searches mean

The 10-request benchmark projected approximately 71 Text Search requests for 1,000 domains at the >=20 review threshold. The real scaled run required **92**.

The gap is expected because scaled discovery encounters:

- markets returning fewer than 20 results
- Google Place IDs that fail strict Grounding identity matching
- no website resolved for some places
- firms below the minimum review count once Grounding is parsed
- repeated website domains / multi-office firms

The measured production-style number (92) should now replace the benchmark projection for planning.

## Geographic coverage

The run used 92 markets across the United States and stopped after reaching 1,000 unique domains. Texas was not the primary source and was not reached before the target was achieved.

The markets used ranged across Arizona, Nevada, Colorado, New Mexico, Utah, Idaho, Washington, Oregon, California, Hawaii, Alaska, Oklahoma, Missouri, Nebraska, Kansas, Iowa, Minnesota, Wisconsin, Illinois, Indiana, Kentucky, Tennessee, Alabama, Mississippi, Arkansas, Louisiana, Florida, North Carolina, South Carolina, Virginia, Washington DC, Maryland, Delaware, Pennsylvania, Ohio, Michigan, New York and Connecticut.

## Review-volume quality of the final 1,000

The final working set uses a minimum of 20 reviews. The first build's review-count distribution is strong enough that the next stage does not need review text.

The final set contains firms ranging from 21 reviews into the thousands; the median review count in the final 1,000 was approximately **120**.

## Website verification caution

Grounding Lite was very strong, but it must not be treated as infallible.

Of the final 1,000 domains:

- **975** passed the basic open-web/domain-continuity verification used in the build.
- **25** did not pass that basic verifier and must be treated as `Needs Review` until Crawl4AI/manual verification.

Reasons include:

- bot protection / no response to a basic HTTP client
- redirects to a different domain
- stale or suspicious-looking website URLs

A small number of the non-verified examples clearly demonstrate why the architecture must preserve the final independent website-validation stage rather than trusting the Grounding summary blindly.

Therefore the output is correctly named a **working set**, not 1,000 fully service-gap-qualified leads.

## Next stage

Do not deep crawl these 1,000 websites.

Process them in batches through the existing homepage-only Crawl4AI collector:

```text
verified/resolved website
→ one homepage render
→ collect same-domain homepage/header/footer/navigation links
→ ChatGPT/manual service-gap check
→ Qualified / Disqualified / Not Relevant / Needs Review
```

The 25 domains that failed basic open-web verification should be prioritized for retry/review before normal qualification.
